## Listen: what's playing around you

Like Shazam: tap **Listen**, hold your phone or computer near the music, and a few seconds later
it tells you the song. **Play** plays it; **Play from here** picks it up from the moment it's at
in the room. Everything it recognises is kept under **Recently heard**.

- **Where to find it:**
  - **Web player:** the sidebar, or the button in the search box.
  - **Phone app:** the button on the Search tab.
  - **Desktop app:** the sidebar.
- **Your own library first, on your server.** The server now learns every song in your Jellyfin
  libraries (their audio fingerprints, the technique Shazam uses). It works in the background, a
  few seconds a song, and starts a minute after the server does. Listen then recognises those
  songs from a few seconds through a microphone, noise and all, without anything leaving your
  server. It usually knows within four seconds, and keeps listening up to ten when the room is
  noisy.
- **Anything else, with AudD (optional).** Add AudD in **Settings › Sources**, like any other
  source, with your own API token from audd.io (300 recognitions free, then paid per
  recognition). Only what your library didn't recognise goes to AudD, and Listen finds the song
  on your sources so you can play it.
- **The microphone:** the web player asks for it the first time you listen. Browsers only allow
  it on pages opened over HTTPS. The phone app asks the first time too.
- **Space:** what Listen learns takes about 15 MB for every 100 songs, in `listen.db` in the
  server's data folder. It doesn't need backing up, because the server learns it again if it's
  gone. An admin can turn learning off in **Admin › Settings**.

In tests on real music played through a simulated phone microphone across a room, with
background noise, Listen recognised most clips within four seconds. It never named the wrong
song.

Also: the desktop app can now jump about in songs the server is converting (with a bitrate cap
set), as the web player already could.

Update the server first.
